# 220 GHz THz 双向主动对准阶段三、四：前馈移植与验证记录

## 工作边界与证据口径

本轮从已有 MATLAB 阶段一二骨架、阶段三四融合试验和师兄提供的 220 GHz Python 模型继续推进。集成入口是 `run_thz_stage3_4.m`，六状态顺序为 `x=[q,q_dot,e_H,e_E,omega_H,omega_E]^T`；角度与角速度分别使用度和度每秒。方向图由实测天线 Excel 读取，H/V 半功率波束宽度为 0.7026°/0.8328°。所有本轮数字均为固定种子下的本地单次 MATLAB 仿真，不是硬件闭环，也不是统计显著性结论。

需要先说明一个与预期叙述不同的结果：前馈项已经移植并进入控制命令，但本轮前馈并未让两轴、两种半径策略都稳定锁定。论文半径模式下，Rover 末端误差从无前馈的 31.0172° 降至 17.0313°，Elevator 则从 22.3610° 增至 30.6400°。THz 自适应半径模式下，无前馈为 20.6321°/19.3862°，加入前馈后为 25.7939°/14.4918°。这些结果要求我们把“机制移植完成”和“跟踪成功”严格分开。

## 六状态前馈与时间尺度

师兄 Python 的 `_AgeAwarePolicy` 将反馈项与角速度预测项相加，基本结构是 `correction = clip(feedback + omega_hat * actuation_delay, limits)`。`MotionPredictivePolicy` 沿用相同角速度前馈接口。源码明确把样本 age 放在 IEKF 测量模型中做异步对齐，并把前馈跨度解释为状态参考时刻至命令生效的因果时延；它不把旧样本龄期再加一次。因此本 MATLAB 迁移将 8 秒定义为本工程长时隙执行延迟假设 `tau_ff=2*ns*dt=2*8*0.5=8 s`，并单独记录，不能误称为师兄 Python 默认的云台机械延迟。

Active 控制在当前本地状态符号下实现为 `u=Kp*e+Ki*integral(e)+tau_ff*[omega_H;omega_E]`，随后按 `max_command_deg` 限幅。用户给出的负号公式属于另一种误差定义；如果误差定义改成“波束减 LOS”而不是当前代码的“LOS 减波束”，符号也必须整体改变。把公式抄成相同符号并不等于控制方向相同，符号必须由 plant 的几何约定和一次小扰动试验校准。仿真输出额外保存两轴前馈分量，便于检查预测量是否被限幅或反向放大。

角速度状态按常速模型传播：`e_H(t+tau)=e_H(t)+tau*omega_H(t)`、`e_E(t+tau)=e_E(t)+tau*omega_E(t)`。Active IEKF 的状态转移矩阵在 `(e_H,omega_H)`、`(e_E,omega_E)` 两个位置填入批次时间间隔，协方差按 `P-=Phi*P*Phi'+Q` 传播。本调度中同一端每隔 16 拍重新 Active，间隔正好 8 秒；每个扫描样本的采集年龄另行进入测量模型。前馈与样本时间戳因此各司其职，不重复计时。

## Passive 标量更新和 Schur 补

Active/Passive 调度每 16 拍循环一次：前 8 拍 R1 Active、R2 Passive，后 8 拍互换。Passive 端扫描半径和电机控制均强制为零。论文 III-D 指出零半径下重复观测的角度敏感方向消失；单个功率观测对六维状态至多给出一个独立约束，观测矩阵秩为 1。此时若直接执行 6×6 EKF 更新，滤波增益可能借助数值交叉项改写实际不可观测的角度与角速度方向，造成“有更新数值、没有新信息”的漂移。

实现因此绕过完整六维更新，只按式（27）至（31）处理功率标量：`q-=q`，`P11-=P11+Q11`，`K1=P11-*C1/(C1^2*P11-+R)`，再只更新 `q` 和 `P11`。`x(2:6)`、`P(2:6,2:6)`、`P(2:6,1)` 与 `P(1,2:6)` 都从更新前直接复制。160 拍零速运行中，这些受保护量的最大差为 0，小于 `1e-12` 容差。这里的“冻结”是逐项不变，而不是通过事后把角度滤波结果拉回原值来近似实现。

固定交叉协方差而减小 `P11` 可能使全协方差不再半正定。把矩阵按功率标量和其余五个状态分块，若 `P_rest` 正定，半正定的充要 Schur 条件是 `P11 >= p' * inv(P_rest) * p`；半正定或病态情形用广义逆并检查其值域条件。代码在式（31）后将允许变化的 `P11` 抬到该下界，并加数个机器 epsilon 以抵消浮点舍入。这个约束只是在冻结所有其他元素的前提下守住 PSD 边界，不会增加角度信息，也不能保证矩阵最小特征值“必然等于”`1e-15`。实际特征值需由运行结果报告；接近 `1e-16–1e-15` 是当前尺度下的数值观察，不是 Schur 定理给出的固定值。若 `P_rest` 奇异、交叉项不在其值域内，或输入矩阵本已非 PSD，应报错/诊断，而不应悄悄用任意对角抖动掩盖。

## 半径自适应与实测主瓣

对角度协方差子块 `P_ang=P(3:4,3:4)`，在对称半正定条件下，谱范数等于最大特征值：`||P_ang||_2=lambda_max(P_ang)`。式（25）、（26）把窗口内该量汇总后，经 `K_delta` 映射并限幅。论文半径模式使用 2°–5°限幅，`K_delta=1/(7000*ns)` 将作者 `NodeEKF.m` 中“窗口均值再除以 7000”的代码尺度换算成窗口求和形式；这不是论文普适常数。另一条 THz 工程半径模式将较窄实测 HPBW 的 0.1–0.5 倍作为限幅，即约 0.0703°–0.3513°。两者均采用同一测量方向图与随机种子，便于拆分半径尺度和前馈的影响。

在未加前馈的已有运行中，论文半径模式末端误差为 31.0172°/22.3610°，THz 亚度半径模式为 19.9647°/16.6313°。这组数字说明亚度扫描半径本身没有解决失锁，不能据此归结为“半径太大”一个原因。空间扫描尺度与时间更新周期是两个不同条件：窄半径可使扫描点留在主瓣附近，却无法让 8 秒后才发出的控制命令作用于 8 秒前的 LOS；控制器看到的是旧参考状态，移动已经改变了目标方向。若角速度估计、符号、参考时刻或量测模型任一不一致，缩小扫描半径甚至会减弱捕获激励，使滤波器更难发现偏差。该组结果支持“空间尺度变小不等于时间延迟被补偿”，并不单独证明时间错配是全部发散原因。

理想的前馈图像是：Active 批次给出 `omega_hat`，控制器用 `tau_ff*omega_hat` 估计命令生效时的视线位移，再把波束中心移向未来 LOS，而非只追赶当前误差。若估计方向、轴定义、坐标变换和时延都正确，这相当于沿相对运动轨迹提前布点。对 0.7°量级 HPBW，几分之一度的预测误差已经可能显著改变接收功率，因而前馈是否生效必须通过逐轴误差、命令分解、饱和标志和主瓣内占用时间共同判断。当前结果尚未显示“成功咬合主瓣”：论文半径下只改善一轴，THz 半径下本次两轴都退化。应优先核对状态误差符号与 `omega` 是视线角速度还是误差角速度、两个终端本地切平面到世界坐标的符号映射、8 秒预测期间速度是否近似常值、控制限幅与积分项是否冲突，以及测量参考时刻和移动更新顺序是否一致。

## 本轮运行记录

MATLAB R2023a 主入口同时执行 160 拍零速静态断言、200 拍速度因子 0.2 正交移动，以及论文半径/THz 半径和前馈开/关四种配对。静态测试中两种半径模式的 Passive 冻结误差均为 0；实测方向图 HPBW 为 0.7026°/0.8328°。动态距离从 2.3000 m 变化到 2.3087 m。无前馈与有前馈末端误差如下，均为单次固定种子结果：

| 半径模式 | 前馈 | Rover 末端误差 | Elevator 末端误差 |
|---|---:|---:|---:|
| 论文 2°–5° | 关闭 | 31.0172° | 22.3610° |
| 论文 2°–5° | 开启，8 s | 17.0313° | 30.6400° |
| THz 0.0703°–0.3513° | 关闭 | 20.6321° | 19.3862° |

因此当前结论是：六状态角速度前馈接口已经进入 MATLAB 闭环，零速 Passive 安全断言仍通过，但闭环稳定性没有通过。前馈对不同轴和半径政策呈现相反影响，不能汇总成总体改善。该对照使下一轮排错有明确方向：先做零速有/无前馈等价测试，再对 H/E 轴分别注入已知正负 LOS 角速度，验证控制补偿方向；随后检查命令限幅和 PI 积分器，最后再做速度扫描与多随机种子统计。作者 Fig. 8/10 归档可作为论文算法语境对标，但并非 THz 前馈对比，不应与上述本地运行混表。

## Word 汇报正文

### 220 GHz 太赫兹双向主动对准阶段三、四进展汇报

这轮工作从我前期手写的 MATLAB 阶段一、二骨架继续做。原始代码用 LED 通信的高斯角度响应验证了 EKF、PI 和扫描逻辑；迁到 220 GHz 后，最先遇到的不是滤波器维数问题，而是天线尺度变了。师兄提供的实测天线表格显示 H、V 两轴 HPBW 大约只有 0.7026° 和 0.8328°。原来以度为单位的扫描半径，放到这个主瓣上已经不能直接照搬。

我先把 MATLAB 的测量模型换成实测方向图插值，并按师兄 Python 模型的状态定义扩到六维：功率基线、功率变化率、H/E 指向误差以及 H/E 视线角速度。角速度状态不是为了让状态看起来更完整，而是因为两次功率扫描之间目标方向会继续移动。然后我逐段检查了 Python `_AgeAwarePolicy` 和 `MotionPredictivePolicy`：它们都把角速度乘执行延迟形成前馈，叠加到反馈命令；样本采集年龄则已在 IEKF 中单独处理，不应再重复计入预测时延。

本轮把 8 秒作为 MATLAB 长时隙下的命令生效预测跨度，具体是 `2*ns*dt=2*8*0.5` 秒。这里我需要把来源说准确：8 秒是本复现的时隙延迟假设，不是 Python 里默认的云台机械延迟。当前控制代码按本地“LOS 减波束”的误差约定实现反馈加角速度前馈，并且限制最大命令；下一步还要逐轴验证速度符号和坐标转换，不能只凭公式长得相似就认定符号正确。

阶段三的双向调度已经合进同一个入口。前 8 拍 R1 扫描、R2 被动，后 8 拍角色交换。Passive 端半径和电机命令归零。由于单个功率量测对六个状态只有秩一信息，我没有在这个阶段继续跑 6×6 EKF，而是严格只更新功率 `q` 和 `P(1,1)`，其余五个状态及所有对应协方差行列原样冻结。160 拍静态运行里，冻结项最大差值为 0，满足 `1e-12` 断言。

我还处理了固定交叉协方差带来的 PSD 风险。标量更新会降低 `P(1,1)`，但如果 `q` 与角状态之间的交叉项保持不变，整张协方差矩阵可能越过半正定边界。因此代码把 `P(1,1)` 限制在 Schur 补下界之上，只调整这个允许更新的标量方差，其他项不动。这个保护的意义是维持协方差合法，不是给被动端补出角度观测；最小特征值落在浮点零附近是运行诊断结果，不是数学上保证固定等于某个数。

扫描半径方面，我保留论文 2°到 5°模式，也加入按实测 HPBW 缩放的 0.0703°到 0.3513°工程模式。两者都依据角度协方差最大特征值形成自适应量，再按各自限幅收缩。我们之前的无前馈运行中，论文半径末端误差是 31.017°和22.361°，THz 亚度半径是19.965°和16.631°。因此，把半径缩到亚度并没有自动解决问题。它解决的是扫描空间尺度，解决不了控制命令在长时隙后才生效的时间错配。

我把角速度前馈移植后，又按相同随机种子跑了前馈开关对照。结果并没有达到预期中的“两端都稳定锁定”：论文半径下 Rover 误差降到17.031°，但 Elevator 升到30.640°；THz 半径下 Rover/Elevator 分别是25.794°和14.492°，表现为一轴变差、一轴改善，且绝对误差仍很大。我的判断是，前馈接口的代码迁移已经完成，但控制方向或时标接口还没有完成验证。最需要优先查的是 omega 状态究竟表示 LOS 变化率还是误差变化率、Rover 与 Elevator 的本地 H/E 轴符号是否一致，以及 PI 积分和命令限幅有没有把预测项截掉或反向放大。

所以这轮汇报的结论不是“已经从发散跨越到稳定锁定”，而是我们把失败推进到了可诊断、可消融的阶段：Passive 不可观测方向有严格冻结；角速度前馈已接入；两套半径和前馈开关已在同一脚本、同种子下配对运行。静态保护通过，动态跟踪仍未通过。下一步我会先在零速和人工注入角速度下逐轴验证符号，再检查 8 秒预测的参考时刻、坐标变换和饱和器；这些接口确认以后，再开展速度扫描和多种子统计。这样才能判断前馈何时真正把波束提前带到未来 LOS，而不是把一个尚未验证的控制假设包装成成功结果。
